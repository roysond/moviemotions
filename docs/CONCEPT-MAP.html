Evals vs. validation — the untangle that matters most

EvalsValidation & guardrails
WhenOffline, deliberately, in batchesOnline, on every single request
Against whatA fixed test set with known-good answersReal traffic, no known answer
Asks“Did my change make the system better or worse?”“Is this one response safe to send?”
BlocksA mergeA response reaching the user
ToolsRAGAS for scores · LangSmith for history · GitHub Actions to run itSchema checks · grounding checks · content safety · least-privilege tool access

They sound alike and are completely different jobs. Evals ask whether the system is good. Validation asks whether this output is acceptable, right now.

Three definitions worth getting exactly right

Semantic search ≠ semantic layer

Semantic search finds things by meaning rather than exact words — “a man stranded on Mars” finds the right film even if the synopsis never says “stranded.” A retrieval technique.

Semantic layer is one agreed place where business terms are defined. In this app: nearby = within 20 miles of the user's ZIP. available tonight = a showing in the next 3 days, or streaming on a service they have. new release = theatrical within 45 days. Defined once — otherwise “new release” quietly means 30 days in one function and 90 in another.

Guardrails live at three points, not in one file

Input — before the model sees the text: injection detection, PII scrubbing, off-topic rejection.
Tool — what the agent may call, with what arguments, how often. Least privilege.
Output — before the user sees it: grounding check, schema validation, content safety.

They apply to plain LLM calls and agentic loops alike — but tool guardrails only exist when there are tools, so agentic systems need strictly more.

LLMOps vs. MLOps

MLOps is the parent discipline: shipping, monitoring, and retraining models. LLMOps is that adapted to LLMs, where retraining is mostly replaced by prompt versioning, eval gates, and managing cost and latency — because usually you aren't training the model at all.

Correction — MCP is not how you call the weather API.

Calling a weather API is an ordinary HTTP request; no protocol required. MCP is a standard for exposing your own tools to AI clients — you'd use it so that something like Claude Desktop could search your movie corpus. It points outward from your system, not inward toward external services. Worth knowing precisely, because an interviewer will hear the difference immediately.

Six things missing from the list

  • Chunking strategyHow text is split before embedding. The single largest lever on retrieval quality, and very few people can explain it.
  • RerankingA second pass that reorders retrieved results. Most of the distance between a demo and production.
  • Structured outputForcing a model to return reliable JSON every time. Constant, practical, unglamorous.
  • CachingThe largest cost lever available.
  • Cost and latency as design constraintsPrecisely what a Solutions Architect is hired to own.
  • Secrets managementAPI keys are arriving. Where they live, and how they never reach GitHub.
