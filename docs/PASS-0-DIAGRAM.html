Pass 0 · the walking skeleton

Every component exists and connects — each one the dumbest thing that works

One source, one chunk per film, cosine similarity, one LLM call, five eyeballed queries. Nothing here is good. Everything here is connected, which is the only property Pass 0 is trying to have.

The pipeline, end to end

1
Ingest
get the data
sourceTMDB API20 films, matched by title + year
▸
landingdata/raw/tmdb_*.jsonthe API response, byte for byte, unmodified
whyKeep the raw thing; derive everything else from it. Every future extraction — a graph, new fields, a different curation — comes from this file, with no re-fetch from an API you don't control. One source only, because you must feel shallow retrieval fail before enrichment means anything.
▼
2
Curate
make it usable
flattentitle + overview + genresno enrichment, no dedupe, no conflict handling
▸
tablemoviesid · source · source_id · fetched_at · raw_payload
whyA field earns a column only when something must filter, sort, join or look it up — everything else stays in raw_payload. UNIQUE(source, source_id) means the database prevents duplicates, not your code remembering to check.
▼
3
Embed
text → vectors
chunking1 film = 1 chunkno chunking strategy at all — deliberately
▸
modelNova 2 Multimodal @ 1024dbenchmarked against Titan on 5 real queries
whyDimension is a property of the model, not a dial — and more isn't "safer", embeddings have no overflow. 1024 sits inside pgvector's 2,000-dim index cap. Measured, not assumed: Nova's baseline similarity is 0.642 vs Titan's 0.126 — a narrow space, which matters later.
▼
4
Storage
where it lives
enginePostgres + pgvectorone database for vectors, keywords and graph
▸
grainchunks • chunk_embeddingschunk vs chunk × model — split after a 40-row bug
whyStoring text once per model duplicated it. Splitting the tables fixed the grain — what one row represents — and incidentally made champion-vs-challenger possible: UNIQUE(chunk_id, model_id) lets two models' vectors sit side by side.
▼
5
Retrieve
find candidates
queryembed(text)
▸
searchcosine similarityORDER BY embedding <=> query
▸
resulttop 5 filmssemantic only — no keywords, no rerank, no filter
whyCrude on purpose. Two facts learned here shaped all of Pass 1: semantic search always returns something (there is no "nothing matches"), and a similarity score is meaningless without the corpus baseline. Also: a single vector loses relationships — The Hangover matched "creatures chasing people" because it has a tiger in a bathroom.
▼
6
Reason
decide & explain
callone LLM call"here are 5 candidates, pick 3, explain why"
▸
outputstrict JSONnever prose you have to parse
whyA straight line, not an agent — on purpose. This is a pipeline: you can draw it before the query arrives. Building it first is how you'll feel the difference when it becomes a loop in a later pass, instead of being told.
▼
7
Serve
expose it
apiFastAPI · POST /recommendtested in the auto-generated docs page — no UI
whyThe exit condition for the whole pass is a human typing a sentence into a form and getting three films back with reasons. It doesn't have to be good. It has to work.
▼
8
Evaluate
is it any good?
method5 hand-written querieseyeballed — no scoring, no automation, no record
whyGood enough to notice something is wrong, not good enough to prove anything. Turning this into a real metric is a Pass 1 job — and the first thing it did was catch a regression this version couldn't see.
