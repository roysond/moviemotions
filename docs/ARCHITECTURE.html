Where the rich scene-level text comes from

A 200-word overview can never match “they confront an animal in the woods.” Three sources, layered:

SourceTierWhat it gives
Wikipedia plot sections2 · CC BY-SA 4.0700–1500 words, genuinely scene by scene. The only free, legally reusable, long-form plot source at scale. This is the primary corpus.
TMDB keywords2Crowd-tagged concepts — “bear attack”, “forest”, “survival”. Short, high-signal, excellent for mood and scene matching.
TMDB overview + fields1Canonical metadata: title, runtime, cast, crew, genres, release date, watch providers.
PDF documents3 · P2Press kits, festival programmes, critic essays. Added later as a second source behind the same interface — and the reason conflict resolution has to exist.

How PDFs get stored — and how contradictions get settled

Where it landsWhat's in it
documentsOne row per PDF: filename, checksum, page count, source, licence, ingested_at. The original file itself stays on disk untouched.
pagesExtracted text per page, with page number kept so any answer can cite “page 7.”
chunksThe same table the movie text uses. One retrieval surface, many source types — distinguished by a source_type column. This is why the search doesn't care where text came from.
claimsWhere contradictions become visible: entity · attribute · value · source · confidence · observed_at. Two rows disagreeing is a detectable state instead of an invisible one.
The rule for contradictions. Precedence is declared per field, never globally — an API may be authoritative on runtime while a press kit is authoritative on billing order. The losing claim is never deleted, only marked superseded, so “why does it say lead?” stays answerable. Low-stakes fields resolve silently; high-stakes ones get flagged to a human. And who sets the precedence order is a governance decision, not an engineering one.
