A The eight components, side by side

Every pass walks all eight. Only their depth changes.
1 · Ingestget the data
Pass 0One source (TMDB). 20 films fetched by title+year. Raw JSON kept unmodified on disk.
Pass 1Second source added: Wikipedia plot sections, joined IMDb ID → Wikidata → article — never by title, because titles collide (2010 vs 1984 Karate Kid). Survived a Wikimedia 403 robot-policy block. Every record stores a fidelity flag. Bought: real integration engineering — identifier joins, blocked endpoints, provenance
2 · Curatemake it usable
Pass 0Flatten to title + overview + genres. No enrichment. 348 chars per film, naming zero scenes.
Pass 1Three text layers per film: overview (facts), derived (LLM-written feel/moods/themes), plot (~4,000 chars, 20+ scenes). Two records caught as silently summarised at ingest and re-fetched. Bought: AI-ready data curation, and proof that ingest can degrade data quietly
3 · Embedtext → vectors
Pass 0One film = one chunk. No chunking strategy at all. Nova 2 @ 1024 dims, chosen by benchmark.
Pass 1Hybrid chunking: semantic → recursive → overlap. Sentence embeddings locate meaning shifts; recursion enforces the size cap by cutting at each segment's own biggest shift; overlap stitches only the 39 size-forced seams. Plus contextual headers on every chunk. Vectors cached by SHA-1 of content. Bought: chunking as a measurable lever, not a default
4 · Storagewhere it lives
Pass 0movies + one embedding each. Postgres + pgvector.
Pass 1chunks (grain: chunk) split from chunk_embeddings (grain: chunk × model), so champion and challenger vectors coexist. 185 chunks across 3 source types. Per-film commits make ingestion resumable. Bought: correct grain, and checkpointed pipelines
5 · Retrievefind candidates
Pass 0Cosine similarity, top 5. Semantic only. No reranking, no filtering, no fusion.
Pass 1Stratified candidates → cross-encoder rerank → damped aggregation → collapse to films. Reranker hosted on OpenRouter after three AWS access walls; wrapped so an outage costs quality, not availability. Bought: the entire retrieval story — five measured failures, section C
6 · Reasondecide & explain
Pass 0One LLM call: "here are 5 candidates, pick 3, explain." A straight line — deliberately not agentic.
Pass 1Unchanged — on purpose. Still a pipeline, not a loop. This is the next build: LangGraph orchestration, tool registry, ReAct, human-in-the-loop, LangSmith tracing. Deliberately deferred — the honest gap
7 · Serveexpose it
Pass 0One POST /recommend endpoint, FastAPI, tested in auto-generated docs. No UI.
Pass 1Unchanged. CLI search.py now reports score + method so every answer says how it was produced. Small but real: answers are self-describing
8 · Evaluateis it any good?
Pass 0Five hand-written queries, eyeballed. No scoring, no automation, no record.
Pass 1eval_cases.json as a golden set. Verdicts print PASS n/m, not a bare PASS. A WATCH case records a known corpus gap rather than faking a pass. Bought: a metric that can see decay — it caught three regressions

B The retrieval pipeline, before and after

Pass 0

query ──▶ embed ──▶ cosine top-5 ──▶ answer

Pass 1 — same query in, same shape out, four new stages between

query ──▶ embed │ ├─▶ STRATIFIED CANDIDATES top 30 plot · top 10 derived · top 10 overview │ each type ranked within its own kind, so short chunks cannot crowd out long ones │ ├─▶ RERANK (cross-encoder) reads query + chunk together — the only stage that can │ tell "creatures hunting people" from "a tiger in the bathroom" │ ├─▶ AGGREGATE PER FILM score = best + 2nd/2 + 3rd/3 │ breadth of evidence beats one lucky scene │ └─▶ COLLAPSE TO FILMS small-to-big: match a scene, return the film ──▶ answer
The components did not change. Their order and their inputs did — and that was worth 3 recall points.

C Five measured failures — how retrieval actually got fixed

None of these were found by reading code. Each was found by measuring, and each produced a rule.
4/7
1 · Baseline — vector only

Semantic search over 40 chunks. "Creatures chasing you" returned Predator and two wrong films; The Hangover surfaced because it has a tiger in a bathroom.

5/7
2 · Add a reranker

A cross-encoder reads query and document together. Tiger demoted 5×. But Finding Nemo dropped out — a stricter reader exposed that its text was abstract. A better model exposes thin content; it does not fix it.

4/7
3 · Add 136 plot chunks — no change at all

Scores identical to four decimals. DISTINCT ON (m.id) collapsed to one chunk per film inside the SQL, and a 120-char mood blurb beat its own film's 600-char scene on cosine every time. The plot corpus never reached the reranker.

4/7
4 · Collapse after reranking instead

Right fix, still not enough: for an abstract query every short chunk out-scored every long one, so a global top-30 contained zero plot text. Fixed by stratifying quotas per source type. Predator returned to #1 — but one lucky scene could still carry a film, so scoring became a damped sum of a film's top three chunks.

7/7
5 · Contextual headers — the breakthrough

Finding Nemo's separation scene was retrieved (rank 3) and still lost. Read as the cross-encoder sees it, the chunk says "Nemo swims to a speedboat and is captured" — no "father", no "son", no search. Chunking had severed the relationships. Prepending a film-level header to every chunk took case 1 from 1/3 to 3/3 and put Finding Nemo at #1.
